# 渲染与预览组件

在页面中用 **CSS Grid** 组织多个**预览框**；每个预览框负责单关卡的**可视化和变换**（旋转、镜像、Z 层、标签），并与编解码结果、导入导出数据同步。

## Tile3 棋盘与美术资源

- **玩法形态**：**Tile3** 叠层棋盘（**羊了个羊**一类）：多张牌在 **XY 上可重叠占位**，沿 **`z`（层）** 叠放；渲染时需表现遮挡、可点击「顶层露出」区域等（具体交互规则由产品定）。  
- **棋子贴图**：使用 **`src/assets/`** 中的资源；**先绘制底板** `tilebase_<Variant>.png`（如 `tilebase_Cloud.png`），可选叠牌面 `tilebase_card_<Variant>.png`，由 `src/assets/tileSources.js` 解析路径（`ASSETS_BASE = 'src/assets'`）；与 `level_str` 花色字段的映射由该模块维护，**不写入**编解码核心。  
- **懒渲染（虚拟列表）**：CSV / JSON 大量导入时，所有条目先以**骨架占位**（`.bp-cell-skeleton`）插入网格，仅当骨架进入视口（含 `rootMargin: '600px 0px'` 预渲染区）时才创建 `board-preview-cell` 并解码、渲染。已水合的预览框**不会被卸载**，保留用户编辑；导出时未水合的条目按导入快照（无操作、无标签）参与，已水合的取自当前预览。状态行 `.bp-app__grid-info` 显示「共 N · 已渲染 M」。  
- **与 2×2 占位**：每张牌在布局栅格上仍占 **2×2 格**（见下节）；叠层时在相同锚点邻域内多牌 `z` 不同，绘制顺序按 `z` 从大到小或按产品约定。

## 布局层级

```
页面容器 (display: grid)
├── 预览框 A (grid item，如 <board-preview> 或独立 div)
├── 预览框 B
└── ...
```

- **页面级网格**：列数/行数、间距、响应式断点（如窄屏改为单列）在本层用 CSS 控制。  
- **关卡内棋盘**：由预览框**内部**自行布局（可为另一套 grid / absolute 叠层等），与页面 Grid 分离。

## 棋子占位（渲染网格）

- 每个棋子在**关卡内棋盘**的展示用布局上，**宽度占 2 格、高度占 2 格**（即 **2×2 单元格** 一块牌面）。  
- 实现上可为 CSS Grid 子项设置 `grid-column: span 2`、`grid-row: span 2`，或等价绝对定位下的宽高为「单格尺寸 × 2」。  
- **与编解码坐标的关系**：`format.py` 中每条记录仍是一个 `(x, y, z)`（行、列、层）。**`(x,y)` 为棋子 2×2 占格的左上角**；渲染层占 `grid-row/column: span 2`。对棋盘做几何变换后，数据侧须**重新规整为左上角坐标**（见 [Board 操作集](board-operations.md) 与 `boardOperations.js`）。  
- **叠放与命中**：Tile3 下多牌可同锚点邻域叠放，**点击检测、拖拽、层序（`z`）** 需在 2×2 范围内与层序规则一致；与其它牌占用格重叠时的规则（禁止重叠 / 允许叠放等）由产品定义并在 UI 与校验中统一。

## 预览框职责

| 能力 | 说明 |
|------|------|
| 接收数据 | 从父层传入 `levelStr` 或已解码列表；变更时重新渲染。 |
| 解码渲染 | 内部调用编解码模块；解码失败时展示错误态，不白屏。 |
| 左右旋转 | 见 [Board 操作集](board-operations.md) 中 `rotate_left` / `rotate_right`。 |
| X / Y 镜像 | 见 [Board 操作集](board-operations.md) 中 `mirror_x` / `mirror_y`。 |
| Z 轴反转 | 见 [Board 操作集](board-operations.md) 中 `flip_z`；并设置 `hadZAxisOperation`。 |
| 标签 | 展示默认标签列表；支持用户输入自定义标签字符串；标签参与筛选导出。 |

## Web Components 拆分建议（无第三方库）

| 元素（示例名） | 职责 |
|----------------|------|
| `<board-preview-app>` | 网格容器、文件拖入/按钮委托、全局导出 |
| `<board-preview-cell>` | 单格：内部棋盘 DOM、工具条（旋转/镜像/Z/标签）、错误与 loading |
| 可选 `<board-tile-layer>` | 仅渲染单层或单牌，便于测试 |

使用 **Shadow DOM** 时注意：全局样式不穿透，需在组件内自带基础样式或通过 CSS 变量由外层注入主题色。

## 状态与数据流

推荐单向数据流：

1. 父组件持有 `cells: Array<{ id, levelStr, tags, operations, ... }>`。  
2. 子预览框通过 **自定义事件**（如 `levelchange`）或回调上报新 `levelStr` 与操作描述。  
3. 父组件更新 store 后 **再下发** `levelStr`，避免子组件与父状态长期双写不一致。

变换的两种实现策略（二选一并在文档/代码中写死）：

- **视图变换**：仅 CSS `transform`，导出前将变换**烘焙**进数据（需几何逆变换到 `levelStr`）。  
- **数据变换**：每次点击直接改结构化数据再编码；视图仅反映数据。后者更易与 `format.py` 一致，前者更省重绘但烘焙逻辑复杂。

## 无障碍与交互

- 所有工具条控件提供 **可聚焦** 与 **键盘操作**（若产品要求）。  
- 解码失败、导出失败使用 **role="alert"`** 或明确文案区域，不仅依赖 `console.error`。

## 与其它组件的契约

- **编解码**：预览框内不复制解析规则，统一调用编解码模块。  
- **导入导出**：不负责读盘；仅上报/接收父层下发的 `levelStr` 与标签。  
- **操作记录**：每次产生可逆或不可逆变换时，向父层追加一条 `operations` 记录；几何类 `type` 与坐标公式见 [Board 操作集](board-operations.md)，标签类见同页文末。
