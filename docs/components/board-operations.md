# Board 操作集

本页约定 **Tile3 叠层棋盘**（羊了个羊类）单个关卡在预览框内可执行的**几何变换**类型、对结构化数据（与 [编解码组件](codec.md) 中 `x` 行、`y` 列、`z` 层、`suit` 花色一致）的影响，以及写入导出包时 `operations` 数组的**记录格式**。标签类操作（增删改标签）不在此「几何操作集」内，仍可在同一 `operations` 流中用单独 `type` 记录，见文末。

## 棋子占格与坐标（实现必读）

- 每个棋子在网格上占 **2×2** 格。  
- 数据中的 **`(x, y)` 为该棋子占格的左上角**：行下标 `x` 与 `x+1`、列下标 `y` 与 `y+1`（同一 `z`）。  
- 对整块棋盘做旋转 / 镜像时，实现上应对该牌的 **四个格点** 同步套用与下文一致的变换，再取变换后格点的 **最小行、最小列** 作为新的左上角写回（**重新规整为左上角坐标**）。  
- 变换参考包围盒按 **所有棋子占格并集** 计算：行范围为 `min(x)` 至 `max(x+1)`，列范围为 `min(y)` 至 `max(y+1)`（见 `getFootprintCellBounds`）。  
- 下文公式若写为单点 `(x,y)`，等价于「仅锚点」近似；**2×2 语义**以 `src/board/boardOperations.js` 为准。

## 操作类型一览

| `type`（建议枚举值） | 名称 | 作用概要 | 是否视为 Z 轴相关 |
|---------------------|------|----------|-------------------|
| `rotate_left` | 左旋转 | 在 **XY 平面**上逆时针旋转 90°（俯视「左转」） | 否 |
| `rotate_right` | 右旋转 | 在 **XY 平面**上顺时针旋转 90° | 否 |
| `mirror_x` | X 向镜像 | 沿 **行方向**的对称轴翻转（交换「上下」观感，对行为 `x` 取关于水平中心线的对称） | 否 |
| `mirror_y` | Y 向镜像 | 沿 **列方向**的对称轴翻转（交换「左右」观感，对列为 `y` 取关于垂直中心线的对称） | 否 |
| `flip_z` | Z 轴反转 | 对 **层索引 `z`** 取关于当前关卡层范围中心的对称，等价于叠放顺序反转 | **是** |

实现 UI 时，按钮文案可与上表「名称」一致；**导出与回放**必须使用稳定的 `type` 字符串。

### 操作记录字符表（UI 紧凑显示）

与 `operations` 数组顺序串联，用于预览框内的「操作记录」一行展示（实现见 `src/board/operationGlyphs.js`）：

| `type` | 字符 |
|--------|------|
| `rotate_left` | `L` |
| `rotate_right` | `R` |
| `mirror_x` | `X` |
| `mirror_y` | `Y` |
| `flip_z` | `Z` |

若某次交互在数据层等价于多次上表操作的复合，仍建议**按用户点击**逐条追加记录，便于复盘；若产品选择只存「最终串」可不展开。

## 先决：包围盒（占格并集）

以下公式用于理解单点 `(x,y)` 时的代数形式；**2×2 实现**以 `getFootprintCellBounds` 为准：对全体棋子的占格取并集，行范围为 `min(锚点行, 锚点行+1)` 至 `max(…)`（列同理），即所有被占格子的行列闭区间。

- `xmin, xmax`：行方向**占格**最小、最大索引  
- `ymin, ymax`：列方向**占格**最小、最大索引  
- `zmin, zmax`：`z`（层）的最小、最大值  

单张牌变换后 **花色 `suit` 随该张牌移动**（与坐标同一元素），不在镜像/旋转中单独对调字符。

变换完成后，若编解码管线要求有序列表，可按 `(z, x, y)` 排序后再编码（与 `format.py` 中 `sort` 一致）。

## 各操作的数据语义

对 **2×2 棋子**：先将四角 `(x,y),(x+1,y),(x,y+1),(x+1,y+1)` 各点套用下式（`z` 同层），再取结果点的 **最小行、最小列** 为新锚点。以下公式以单点 `(x,y)` 书写，便于对照；与代码完全一致时需按上节「占格并集」理解 `xmin,xmax,ymin,ymax`。

> 渲染坐标约定：`x` 为**行**（向下递增），`y` 为**列**（向右递增）。下面 `rotate_left` / `rotate_right` 都按**屏幕视觉方向**命名：左转 = 视觉上逆时针 90°，右转 = 视觉上顺时针 90°。

### `rotate_left`（视觉逆时针 90°）

把右上角带到左上角、左上带到左下、左下带到右下、右下带到右上：

\[
x' = y_{\max} - y + x_{\min},\quad y' = x - x_{\min} + y_{\min},\quad z' = z
\]

当 `x_{\min} = y_{\min} = 0` 时，退化为 `x' = y_{\max} - y,\; y' = x`。

### `rotate_right`（视觉顺时针 90°）

\[
x' = y - y_{\min} + x_{\min},\quad y' = x_{\max} - x + y_{\min},\quad z' = z
\]

当 `x_{\min} = y_{\min} = 0` 时，退化为 `x' = y,\; y' = x_{\max} - x`。

### `mirror_x`（行向镜像，关于行方向中心）

\[
x' = x_{\max} + x_{\min} - x,\quad y' = y,\quad z' = z
\]

### `mirror_y`（列向镜像，关于列方向中心）

\[
x' = x,\quad y' = y_{\max} + y_{\min} - y,\quad z' = z
\]

### `flip_z`（层索引反转）

\[
x' = x,\quad y' = y,\quad z' = z_{\max} + z_{\min} - z
\]

应用任一次 `flip_z` 后，应将导出元数据中的 **`hadZAxisOperation`** 置为 `true`（与 [导入导出组件](io.md) 一致）。若同关卡多次 `flip_z`，该标志保持为 `true` 即可。

## 导出中的单条记录形状

与 [导入导出组件](io.md) 中的 `operations` 数组配合，建议每条为：

```json
{
  "type": "rotate_left",
  "payload": {},
  "at": "可选 ISO8601 时间戳"
}
```

- **`payload`**：本操作集上述五种几何操作可为空对象；若未来需要「相对某参考框」等扩展，再在此放入参数而不改 `type`。  
- **回放顺序**：与数组下标顺序一致，在**同一份 `sourceLevelStr` 解码结果**上依次应用，应得到当前 `levelStr`（若中间有其它非几何操作，需单独定义其语义）。

## 与渲染实现的关系

- **数据变换路径**：每次点击直接改列表坐标再编码，与本页公式一一对应，最易与导出回放一致。  
- **视图变换路径**：若仅用 CSS `transform` 表现旋转/镜像，导出前必须将等价变换**烘焙**到坐标或得到相同 `levelStr`，否则 `operations` 与 `levelStr` 会不一致。

详见 [渲染与预览组件](render.md)。

## 标签（非几何）

标签的增删改若需进入同一操作流，建议使用独立类型，例如：

- `tag_add` / `tag_remove` / `tag_set`：`payload` 中带 `label: string` 或 `labels: string[]`  

此类操作**不**设置 `hadZAxisOperation`。
